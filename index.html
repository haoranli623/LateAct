The serving problem

The user changes direction while generation is still running.

A few-step video world model produces each block through several denoising network evaluations (NFEs). When a new action arrives mid-block, the server must decide whether the work already completed is reusable.

01

NEXT-BLOCK

Finish the active block under OLD and apply NEW later.

No recomputation, but stale control remains visible for the current block.

02

DIRECT-LATE-BIND

Swap to NEW for whatever NFEs remain.

Cheap, but ineffective once the denoising trajectory has committed.

03

FULL-RESTART

Discard progress and regenerate every NFE under NEW.

Recovers response, but throws away reusable prefix computation.

Key observation

Action recoverability collapses at an operational commitment boundary.

Under coupled state and noise, the action is switched after successive OLD-action NFEs. Normalized response R(s) measures how closely the switched rollout follows the NEW-action oracle.

All 16 Matrix-Game mouse-yaw scene-direction curves pass the frozen validity gates. This is a controlled rollout intervention—not a claim of physical causal correctness or a universal discrete boundary.

Method

Restore the latest safe state—not the beginning.

LateAct converts the measured commitment boundary into a serving rule. Early actions bind directly. Late actions restore the pre-commitment checkpoint and replay only the minimal suffix under NEW.

1

Calibrate

Measure the latest switch point that still recovers the NEW-action oracle under frozen gates.

2

Checkpoint

Audit suffix dependencies and retain exactly the mutable state required to resume there.

3

Serve

Bind directly before commitment; otherwise restore once and replay only the affected suffix.

System design

A compact exact checkpoint, not lossy compression.

The first exact implementation copied current visual and action K/V slices. Static and runtime tracing showed that NFE2 overwrites those current-block positions before reuse, while historical and cross-attention state stay live by reference.

  • 337,920 B entering-NFE2 BF16 latent
  • 1,440 B defensive cache-index state
  • 339,360 B implemented exact checkpoint

1,913× smaller than the 649,330,080-byte initial exact implementation and only 1,432 bytes above the measured logical minimum.

What I built

An audited intervention and serving stack—not just a metric.

The repository implements the complete path from denoising-loop intervention through rollback, asynchronous evaluation, and independent-model mechanism replication.

In-loop action switching

Controlled OLD→NEW substitution at individual NFEs with explicit, hash-matched initial and re-noising tensors.

Exact rollback state

Full and logical checkpoint implementations with scheduler, RNG, cache-index, and bit-exact replay audits.

Branch-safe cache handling

Single-hook K/V insertion plus guards that fail if historical visual, action, or cross-attention state changes.

Asynchronous serving simulator

Matched arrival schedules and four policies with measured action-to-pixel latency and NFE accounting.

Evaluation and statistics

Action-specific LK/RANSAC response, SSIM and temporal safeguards, bootstrap intervals, and exact clustered tests.

Independent replication

Native minWM camera-pose interventions with frozen prompts, seeds, thresholds, coupling checks, and failure-preserving chronology.

Limitations

What this result does not establish.

  • Full LateAct efficacy and latency are validated only for Matrix-Game mouse-yaw.
  • Keyboard transfers the commitment boundary and response, but misses the frozen trajectory-fidelity safeguard.
  • minWM validates the commitment mechanism only; rollback and latency were not tested there.
  • Arrivals are controlled and stratified, not measurements from a production serving deployment.
  • The boundary is calibrated offline rather than dynamically predicted per scene.
  • No downstream robot or task-success objective is evaluated.
